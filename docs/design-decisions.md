# 設計判断と理由

既存の開発コンテキストから、継続して参照する判断と不採用理由を移した記録です。移設確認日：2026-11-05（各判断の決定日ではありません）。
現在の機能仕様は[機能リファレンス](reference.md)、開発手順は[AGENTS.md](../AGENTS.md)を参照してください。

## 設計判断（理由）

| 判断 | 理由 | 正本・根拠 |
| --- | --- | --- |
| 名前を`WordAsData`ではなく`DocumentAsData`とする | 将来のODT等の可能性を残しつつ、初期実装はDOCXへ限定するため | [設計文書](design-v0.1.md)、README |
| MERGEFIELDとContent Controlを別概念として公開する | プログラムから差し込む項目と、人間との双方向入力項目では意味とライフサイクルが異なるため | README、Coreテスト |
| データ項目にはWord側で明示的な名前付き構造を要求する | 段落番号・ページ番号などは安定した識別子にならず、自由文解析は責務外のため | README、機能リファレンス |
| 既存のTDD工程別コンテキストを維持し、AI-DLCは記録と再開補助に限定する | 開発手順を置き換えず、仕様判断の継続性だけを補うため | [TDD入口](../AGENTS.md) |

## 却下した案

* **共通の`Document.Fields`抽象化**：MERGEFIELDとContent Controlの意味を初期段階で消すため、実際の共通価値が確認できるまで導入しません。
* **Word文書を通常のテキストへ変換して扱う**：フィールドやContent Controlの構造を維持する責務と両立しないため対象外です。
* **PDF化やWordの自動操作をライブラリへ含める**：レイアウト計算や外部アプリ操作は利用側の責務とするため対象外です。
* **段落・ページ・行番号による主識別**：文書編集で安定しないため採用しません。
