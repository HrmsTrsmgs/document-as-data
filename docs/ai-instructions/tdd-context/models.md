# モデル選択の開始方針

共通TDDの参照版。正本は `codex-workflows/skills/tdd-workflow/references/models.md`。

進行役は工程開始前に読む。サブエージェントへの委任は、利用環境で委任機能を使える統括モデルから、起動可能と確認できたモデルへだけ行う。モデル名や系列だけで対応可否を決めず、実在する委任ツールの対応モデルID、推論設定、指定権限を確認する。

委任できる場合の割り当ては次のとおり。

| 担当 | モデル・推論レベル |
| --- | --- |
| Red | 統括と同じモデルID・推論レベル |
| Green | 契約が明確な通常実装は、起動可能なLuna系を第一候補とする。利用できなければ、起動可能な候補の中から作業に適したモデルを選ぶ。推論レベルはユーザー指定と利用環境の制約に従う |
| Refactor | 統括と同じモデルID・推論レベル |

Red・Refactorを委任する場合は統括の実際の設定を確認し、別コンテキストへ同じ設定を明示する。指定を省略する場合は両方を継承するツール仕様を確認する。同じ設定で起動できない場合は、黙って別モデル・別推論レベルへ変更せず、その工程を統括が担当する。

サブエージェントを起動できないモデル・環境では、統括が現在のモデル・推論レベルのまま工程を担当する。起動できないことを理由に作業を止めたり、モデルを無断で変更したりしない。Red・Green・Refactorを区別して順番に進め、現在の工程に必要な指示を読み、テスト先行、各工程の作業範囲、ユーザー指定の停止位置、人間レビュー・コミット了承の境界を守る。委任時の履歴分離・専用担当・兼任禁止の規則は、この代行を妨げない。同じコンテキストで実行した事実は示し、履歴を分離できたとは報告しない。

ユーザーの明示指定を優先し、利用できない指定や統括の設定が不明な場合はその事実を報告する。費用や利用枠を未確認のまま断定せず、ユーザーの承認済み範囲を超えない。情報不足は必要資料の取得で解消し、選択の議論を工程担当へ渡したり、工程中に細かくモデルを交代させたりしない。
