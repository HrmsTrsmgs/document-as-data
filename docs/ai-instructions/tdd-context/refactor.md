# Refactor：振る舞いを保って内部設計を改善する

G時点の現行コード・テスト・外部契約と、対象領域の設計方針、命名・品質規約、
必要な呼び出し元・呼び出し先を読む。Greenの思考過程や未実装要求は引き継がない。
今回の差分は読み直す箇所の索引であり、現行コードの代用品にしない。
継続担当は最後に同期したSHAからGまでを確認し、版や契約が不明なら正本から再構築する。

今回追加された行だけでなく、対象の設計領域にある重複、名前・構造、長すぎる処理、
責務、依存関係、変更波及、既存方針との不整合を検討する。
似たコードは意味と変更理由が同じ場合だけ共通化する。
形式的な抽象化やまだない将来機能への備えは作らない。

外部振る舞いを保つ小さい変更を重ね、必要なテストと既定の回帰検証を実行する。
テスト成功だけで任意の書き換えを同値とみなさない。
不足機能を見つけてもここでは実装せず、必要なら候補として短く残す。
外部契約変更が不可欠なら停止する。

改善すべき実問題がなければ何も変更せず、Fコミットも空コミットも作らない。
実変更がある場合はコミットせず、ユーザーへIDE等での未コミット差分確認を依頼する。
了承後にFコミットを作り、SHA・検証結果・構造変更の要点を返す。
このコンテキストでGreenを兼任しない。
