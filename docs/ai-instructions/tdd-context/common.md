# 工程別TDDの共通規則

Red・Green・Refactorは同じ作業ツリー上で順に行い、通常は一工程だけが変更する。
目的は会話履歴の分離であり、担当同士の相談、相互レビュー、AI承認段階を増やさない。
担当は自工程を完了させ、前後の工程を兼任せず、子エージェントへ再委任しない。

リポジトリの `AGENTS.md`、共通の安全・Git規則、ユーザーが確定した契約は維持する。
C#・DocumentAsData固有の指示や設計資料は、今回の工程に必要な箇所を担当自身が調べる。
他工程の指示、会話全文、不採用案、モデル選択の議論は受け取らない。
確定事項、提案、推測、未確認事項を区別し、必要な外部契約が未決定なら停止する。

既存の未コミット差分を保全する。テストのSkipや未実行を成功扱いしない。
Redでは対象テストを実行して意図した失敗を確認する。Green・Refactorの終了時は、
編集中の対象・関連テストに加え、既存のビルド・回帰検証・静的検査を行う。
同じコード・設定・実行条件で既に済んだ検証は、受け渡しだけのために繰り返さない。

Green後と、実変更を伴うRefactor後は、ユーザーがIDE等で未コミット差分を確認する。
対象ファイル、差分の要点、コミットメッセージ案を示し、了承前にステージ・コミットしない。
push、merge、release、権限承認など既存の規則は変えない。

通常の引き継ぎは成果物の場所、確定契約、実行結果、停止理由だけにする。
思考過程や長い会話要約を次工程へ渡さない。
