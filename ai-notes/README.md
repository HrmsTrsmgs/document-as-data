# AIの作業記録

AIが調査・開発を再開するための記録を、Gitで管理します。人間もレビューできる内容にします。
ここは作業指示や確定仕様の正本ではありません。記録された候補は実装の許可を意味しません。

| 記録 | 用途・更新方法 |
| --- | --- |
| [current.md](current.md) | 現在の停止位置、未コミット差分、最新検証、保留、次の一手。再開に不要な完了経緯は残さず、追記日誌にしません |
| [refactoring-review.md](refactoring-review.md) | 全体レビューの根拠・未確認事項・対応状況。最新状態は表で更新し、過去の観測と区別します |
| [repeating-sections-plan.md](repeating-sections-plan.md) | 繰り返し対応の作業計画と検討事項。既存Skipを重複作成しません |

## 置き場所の区別

* 利用方法・制約・長く参照する設計判断は `docs/`。判断と理由は [design-decisions.md](../docs/design-decisions.md)、仕様は[機能リファレンス](../docs/reference.md)とテストへ反映します。
* AIへの指示は [AGENTS.md](../AGENTS.md) と `docs/ai-instructions/`。この場所の調査メモを共通規則へ昇格させません。
* 一時実験、生成物、生ログは既存の無視対象ディレクトリへ置き、この場所には根拠の要約と必要な参照だけを残します。秘密情報や端末固有の絶対パスは記録しません。

## 整理の手順

追加・更新・再開・中断時の整理は、[AGENTS.mdの「仕様・判断と記録先」](../AGENTS.md#仕様判断と記録先)に従います。このREADMEは記録先の案内とし、手順を重複管理しません。
